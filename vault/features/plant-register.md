# Plant register (F9)

> **Hook:** Register a plant once: its name, where it lives, and how it arrived. It gets a short code for its tag and its own page.

Serves: [[every-plant-has-a-past]] · Roadmap: [[roadmap]] (P1, step 2: F9) · Back to [[index]]

## Decisions (2026-11-20)
- **The plant is the protagonist.** A plant belongs to one owner (`owner_id`), who is the only person who can change it. Others see it through public pages later (F4).
- **Place is coarse.** Only city and country code are stored, never coordinates ([[principles]]).
- **Species is optional.** A plant can be registered with a free-text name or a species from the list. The photo-identified species (F9 in [[roadmap]]) comes later.
- **Short code is generated by the database.** It's used for tags and short links, so it's created on insert, not by the app.
- **Only the owner's own rows.** Row-level security lets a signed-in owner read, create and update their own plants. Nobody can delete a plant through the app; memorial and archive are status changes (F14, later).
- **Owner profile comes with it.** Creating a plant needs a profile, so the owner's own profile row is readable and writable by that owner.

## How it works
- `profiles`: the signed-in owner can read and write their own row.
- `plants`: owner-only read, insert and update. `short_code` gets a database default.
- `species`: readable by signed-in users (for the picker); no writes from the app.

## Risks
| Risk | Mitigation |
|---|---|
| A short-code collision makes an insert fail | Unique constraint; the app retries once in the register flow (mobile PR) |
| A plant's owner changes without a handover | Handover is F37, later; the app never reassigns owner_id |

## Photo identification (decided 2026-11-20)
- **Trigger:** the first photo that passes the check for a plant with no species yet. The plant is identified from that photo automatically; the owner doesn't press anything.
- **Model:** Claude Opus 5.5 (`claude-opus-5-5`). Identification is a knowledge-and-vision task on a small number of uploads, so the most capable model is worth the cost. Change the constant in `_shared/plant-identifier.ts` to move to a cheaper model later.
- **Output:** common name, scientific name, family, order, class, category (foliage, flowering, succulent, cactus, fern, herb, tree, other), and a confidence from 0 to 1.
- **Stored:** `species_free_text` (common name), `taxon_family`, `taxon_order`, `taxon_class`, `category`, `id_source = 'photo_api'`, `id_confidence`. The owner can correct it (`owner_correction`).
- **Below 0.5 confidence:** nothing is stored, and the owner picks the species by hand.
- **Failure:** identification is best-effort. An error or unclear answer leaves the plant unidentified and never blocks the photo.
- **Cost:** one vision call per plant (only until it's identified), not per photo.
